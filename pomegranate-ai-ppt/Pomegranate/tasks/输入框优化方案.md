# DeepSeek 插件输入框改进方案

## Context

用户要求将 deepseek-tui 插件的输入框改造为类似 Claude Code 的风格，新增四个能力：
1. 执行权限选择（询问/自动编辑/计划模式/跳过权限）
2. 上下文占用情况指示
3. 可选配置的模型切换
4. Git 仓库信息展示

当前插件使用纯 JavaScript DOM 渲染（非 React），通过 `ctx.app.invoke` 调用 Rust Command。

## 改造范围

| 文件 | 改动类型 |
|------|---------|
| `dev-plugins/deepseek-tui/main.js` | 主要改动 — 新增 UI 组件 + 数据获取逻辑 |
| `dev-plugins/deepseek-tui/styles.css` | 新增样式 — 工具栏行、选择器、进度条、git 状态栏 |
| `src-tauri/src/commands/system.rs` | 新增 `get_git_info` Command（轻量） |
| `src-tauri/src/models/mod.rs` | 新增 `GitInfo` 类型 |
| `src-tauri/src/lib.rs` | 注册新 Command |

**不需要改动的文件**：`src-tauri/Cargo.toml`（不引入新 crate，直接用 `std::process::Command`）

## 架构设计

### 输入区布局（纯 DOM，从上到下）

```
┌──────────────────────────────────────────────────────────┐
│ 🎛 工具栏行 (dt-toolbar)                                    │
│  [模型: deepseek-v3 ▼] [⏺ 询问 ▼] [上下文 12% ████░░░░]   │
├──────────────────────────────────────────────────────────┤
│ ▶ [输入框 textarea.......................................] │
├──────────────────────────────────────────────────────────┤
│ 📊 状态栏 (dt-statusbar)                                   │
│  🌿 master ●1 +2 ~3  │  Ctrl+N 新会话  │  Enter 发送       │
└──────────────────────────────────────────────────────────┘
```

### 数据流

```
插件加载
  ├─→ invoke("list_ai_models")  → 填充模型选择器
  ├─→ invoke("get_git_info")    → 填充 git 状态栏
  └─→ 本地计算上下文占用        → 填充进度条

用户切换模型
  └─→ invoke("update_ai_conversation_model", {id, modelId})

用户切换权限模式
  └─→ 本地状态更新（无需后端）

用户发送消息
  └─→ 携带当前 permissionMode 作为系统提示前缀
```

## 详细设计

### 1. 权限模式选择器 (Permission Mode)

纯前端功能，main.js 中维护 `permissionMode` 变量。选项：

| 模式 | 值 | 图标 | 效果 |
|------|-----|------|------|
| 询问 | `ask` | HelpCircle | 每次操作前询问用户（默认） |
| 自动编辑 | `auto-edit` | Edit | 自动接受文件编辑操作 |
| 计划模式 | `plan` | Map | AI 先出计划，确认后执行 |
| 跳过权限 | `skip` | Zap | 跳过所有权限检查 |

实现方式：在下拉选择器中展示，选中后在发送的消息前自动拼接一段系统指令（如 "请以计划模式工作：先制定计划，等我确认后再执行"）。

### 2. 上下文占用指示器 (Context Usage)

纯前端计算。在每次发送消息和收到回复后，计算当前对话的消息总字符数，与模型 `max_context` 对比。

实现方式：
- 用进度条显示 `usedTokens / maxContext` 百分比
- 颜色三档：绿 (< 50%) / 黄 (50-80%) / 红 (> 80%)
- 数据来源：`invoke("list_ai_messages")` 拿消息列表，计算总字符数；`invoke("list_ai_models")` 拿当前模型的 `max_context`

### 3. 模型选择器 (Model Selector)

需要前后端配合：

**前端（main.js）**：
- 加载时调用 `invoke("list_ai_models")` 获取模型列表
- 在下拉选择器中展示（格式：`provider: model_id (name)`）
- 切换时：
  - 如果已有 conversation → `invoke("update_ai_conversation_model", {id, modelId})`
  - 新建 conversation 时 → 直接传 `model_id` 参数给 `create_ai_conversation`
- 显示当前默认模型（标记 `is_default: true`）
- 选中项高亮

**后端**：无需改动（现有 `list_ai_models` / `update_ai_conversation_model` 已满足需求）

### 4. Git 信息展示 (Git Info)

需要新增一个轻量级 Rust Command。

**新增类型** (`src-tauri/src/models/mod.rs`):
```rust
#[derive(Debug, Clone, Serialize)]
#[serde(rename_all = "camelCase")]
pub struct GitInfo {
    pub branch: Option<String>,
    pub is_clean: bool,
    pub changed: i32,      // 已修改文件数
    pub staged: i32,       // 已暂存文件数
    pub untracked: i32,    // 未跟踪文件数
    pub ahead: i32,        // 领先远程提交数
    pub behind: i32,       // 落后远程提交数
}
```

**新增 Command** (`src-tauri/src/commands/system.rs`):
```rust
#[tauri::command]
pub fn get_git_info() -> Result<GitInfo, String> {
    // 使用 std::process::Command 执行：
    // 1. git branch --show-current
    // 2. git status --porcelain
    // 3. git rev-list --count --left-right @{upstream}...HEAD (容错)
    // 无 git 仓库时返回 GitInfo::default()
}
```

- 使用 `std::process::Command`（不引入新 crate，与 `session_manager.rs` 的 `detect_git_branch` 风格一致）
- 工作目录为 `std::env::current_dir()`（即 Tauri 进程的当前工作目录）
- 容错：非 git 仓库时返回空值（`branch: None`, `is_clean: true`）

**前端展示**：
- 有 git 仓库时：`🌿 master ●3 +2 ~1 ↑1 ↓0`
- 无 git 仓库时：隐藏 git 部分

## 实施步骤

### Step 1: 后端 — 新增 `get_git_info` Command
- 在 `src-tauri/src/models/mod.rs` 添加 `GitInfo` 结构体
- 在 `src-tauri/src/commands/system.rs` 添加 `get_git_info` 函数
- 在 `src-tauri/src/lib.rs` 注册 Command

### Step 2: 前端 — 重构输入区 DOM 结构
- 修改 `DeepseekTerminal.create()` 中的 DOM 构建
- 在 `dt-input-wrapper` 上方插入 `dt-toolbar` 行
- 更新 `dt-statusbar` 内容

### Step 3: 前端 — 实现各功能模块
- 权限选择器：DOM 创建 + 事件绑定 + 消息前缀注入
- 上下文指示器：计算逻辑 + 进度条渲染 + 定时刷新
- 模型选择器：数据加载 + 下拉渲染 + 切换逻辑
- Git 信息栏：数据加载 + 格式化展示

### Step 4: 样式
- 工具栏行样式（flex 布局、间距、按钮/选择器外观）
- 进度条样式（三档颜色）
- Git 状态栏样式
- 保持 DeepSeek TUI 暗色主题一致性

## 验证方案

1. `cargo check` — 验证 Rust 编译通过
2. `pnpm tauri dev` — 启动应用
3. 打开 DeepSeek 终端面板，检查：
   - 工具栏行是否正确渲染（模型选择器、权限选择器、上下文进度条）
   - 下拉模型列表是否显示已配置的模型
   - 切换模型是否生效（查看 conversation 的 model_id 是否更新）
   - 权限模式选择器各选项是否可切换
   - git 信息栏是否显示当前仓库状态
   - 发送消息时系统提示是否随权限模式变化
4. 非 git 目录测试：git 信息栏应隐藏
