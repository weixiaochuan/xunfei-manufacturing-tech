# 插件功能 阶段5 — 安全增强实施计划

> **前置**：阶段 1-4 已完成（运行时 + AppAPI 1.1.0 + UI 注入 + 设置面板 + 错误隔离）。
> **目标**：加固权限校验，防止恶意插件滥用系统资源。
> **原则**：安全边界在 Rust 侧，前端先行的权限检查只是 UX 提示（非安全边界）。

---

## 1. 安全威胁模型

| 攻击向量 | 当前状态 | 风险等级 | 加固方案 |
|----------|---------|---------|---------|
| 插件伪造权限声明（plugin.json 写 `permissions: ["files:read"]` 但用户未授权） | Rust proxy 已做令牌+权限双校验 | ✅ 已防御 | 无需改动 |
| 插件通过 `app.notes.list/update/delete` 越权操作笔记 | Rust proxy 权限校验`notes:read`/`notes:write` | ✅ 已防御 | 无需改动 |
| 插件通过 `app.settings.set/get` 读写其他插件设置 | 键名前缀无隔离，跨插件可读写 | 🔴 高 | 键名前缀自动加 `plugin:{id}:` |
| 插件通过 `app.workspace.getActiveNote` 读到任意笔记内容 | `notes:read` 权限控制，但没限制读取数量 | 🟡 中 | 限额 + 审计日志 |
| 插件 `main.js` 内执行恶意无限循环/内存泄漏 | `new Function()` 同步执行，死循环会冻结 WebView | 🟡 中 | Web Worker 隔离（阶段 6 做，本阶段不做） |
| 插件通过 `new Function()` 构造恶意 DOM/XSS | 插件 JS 在 WebView 主域执行，可任意读写 DOM | 🔴 高 | **Tauri CSP 头收紧** |
| 插件声明 `network:request` 权限后发包到任意域名 | 当前未实现 `network` 能力 | 🟡 中 | 预留设计，本阶段先不做 |
| 插件 `main.js` 中使用 `eval`/`Function` 构造逃逸 | 当前无防护 | 🔴 高 | **CSP 禁止 `unsafe-eval`** |

## 2. 任务拆解（T23-T26）

### T23 — Settings 键名前缀隔离（0.5d）

**现状**：插件调 `app.settings.set("apiKey")` → 写入 `plugin_settings` 表 `key = "apiKey"`。另一个插件也能 `get("apiKey")` 读到（如果被授权 settings 操作的话）。

**加固**：Rust `plugin_proxy_settings_*` Command 在处理 key 时自动添加前缀 `plugin:<pluginId>:`：
- `app.settings.get("apiKey")` → DB key = `plugin:cc:apiKey`
- `app.settings.set("apiKey")` → DB key = `plugin:cc:apiKey`
- `app.settings.getAll()` → 只返回前缀匹配的 key，去掉前缀后返回

**改动位置**：`src-tauri/src/commands/plugin_proxy.rs` 中 settings 3 个 Command。

后端改动量约 30 行。前端 pluginApi.ts 的 `settings.get/set/getAll` 不变，不需改动。

### T24 — CSP 收紧（0.5d）

**现状**：CSP 未显式配置，WebView 默认偏宽松。

**加固**：在 `src-tauri/tauri.conf.json` 的 `app.security.csp` 中收紧：

```
default-src 'self' ipc: https://asset.localhost;
script-src 'self';
style-src 'self' 'unsafe-inline';
img-src 'self' https://asset.localhost data: blob:;
connect-src 'self' ipc:;
font-src 'self';
```

**关键项**：
- `script-src 'self'` — 禁止内联 script（插件用 `new Function()` 不受影响，CSP 管的是 `<script>` 标签注入）
- 禁止 `unsafe-eval` — 但 `new Function()` 实际上也受 `unsafe-eval` 控制，**如果在生产 CSP 中加入这个会导致所有插件都无法加载**。所以：**安全模式开关**：开发/信任模式允许 eval，严格模式禁 eval 但只允许签名过的插件
- 实际策略：不加 `unsafe-eval` 限制（因为 `new Function()` 是当前插件加载的唯一途径），改为通过 `<meta>` 和运行时 API 在插件执行前加运行时隔离

**实际可落地的 CSP**：
```json
"csp": "default-src 'self' ipc: https://asset.localhost; script-src 'self' 'unsafe-eval'; style-src 'self' 'unsafe-inline'; img-src 'self' https://asset.localhost data: blob:; connect-src 'self' ipc: https:; font-src 'self' data:; media-src 'self' https://asset.localhost blob:"
```

**改动位置**：`src-tauri/tauri.conf.json` 的一行 CSP 字符串。

### T25 — 插件数据库权限审计日志（0.5d）

**现状**：权限校验通过就放行，无记录。

**加固**：在 `plugin_proxy.rs` 的 `verify()` 中，每次校验通过时写一条审计日志到 `plugin_audit_log` 表：
```sql
CREATE TABLE plugin_audit_log (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  plugin_id TEXT NOT NULL,
  operation TEXT NOT NULL,   -- "notes:read" / "settings:write" 等
  target TEXT,               -- 操作对象 ID 或 key（可选）
  timestamp TEXT NOT NULL    -- ISO 8601
);
```

插件管理页「详情」Modal 加一个「审计日志」Tab，展示最近 50 条。

**改动位置**：Rust 侧 `commands/plugin_proxy.rs`（verify 加记录）+ `database/plugins.rs`（建表 + 查询）+ 前端插件详情 Modal 加 Tab。

后端改动量约 50 行。前端改动量约 30 行。

### T26 — 插件安装时完整性校验（0.5d）

**现状**：安装插件时只验证 `plugin.json` 存在且格式合法，不校验 main.js 是否与 manifest 一致。

**加固**（轻量版，不做密码学签名）：
1. 安装时对 `main.js` 做 SHA-256 → 写入 `plugins` 表
2. 激活时重新计算 SHA-256 → 与入库值对比 → 不一致则拒绝激活 + 弹 warning
3. 防篡改检测而非防恶意（签名要等阶段 6 市场一起做）

**改动位置**：Rust 侧 `services/plugins.rs`（安装/激活时加 hash）+ `database/plugins.rs`（表加 `content_hash` 字段）+ `commands/plugin_runtime.rs`（激活时校验）。

后端改动量约 40 行。

## 4. 不在本阶段做的事（明确边界）

- ❌ Web Worker 隔离（阶段 6 做，需要设计 Worker 消息协议 + 重建 PluginManager 通信链路）
- ❌ 代码签名 / 证书体系（阶段 6 做，依托插件市场分发机制）
- ❌ `network:request` 域名白名单（当前 `network` 能力未实现，等需求明确再做）
- ❌ 文件沙箱（当前插件不直接操作文件系统，通过受控 proxy 走 db，已隔离）
- ❌ `eval()` 禁止（当前插件加载唯一途径是 `new Function()`，禁 eval 等于禁插件）
- ❌ 第三方安全审计
