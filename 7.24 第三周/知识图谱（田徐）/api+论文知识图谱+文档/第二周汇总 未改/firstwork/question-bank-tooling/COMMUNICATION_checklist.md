## 一、我们对外提供的接口（写清楚：名称、位置、作用）

我们这个模块（题库 + 出题 + 答题反馈）对外一共暴露 **4 组接口**。全部在
`integration/api.py` 和 `demo/serve_quiz.py` 里，Python 直接 import 调用，或走 HTTP。

### 1) 助学接口 —— 给学生出题、收答案、给反馈
| 名称 | 位置 | 作用 | 入参 | 出参 |
|---|---|---|---|---|
| `list_chapters()` | `integration/api.py` | 列出所有章节 | 无 | 章节列表 |
| `get_questions_for_chapter(chapter, n)` | `integration/api.py` | 按章取题 | 章节名、题数 | 题目列表（含题干/选项/配图路径） |
| `get_questions_for_knowledge(knowledge_id, n)` | `integration/api.py` | 按知识点取题 | 知识点ID、题数 | 同上 |
| `submit_answer(question_id, student_answer, **student_id**, mode, use_llm)` | `integration/api.py` | **提交答案，返回判分+反馈** | 题目ID、学生作答、**学生ID**、练习/测试、是否用LLM | 判分、解析、错因、建议、趁热打铁题 |
| `get_student_progress(student_id)` | `integration/api.py` | 学生学情画像 | 学生ID | 已答/正确率/薄弱知识点 |
| HTTP: `POST /api/answer`、`POST /api/ask`、`GET /api/questions` | `demo/serve_quiz.py` | 同上的 HTTP 版 | JSON | JSON |

### 2) 学生 ID 接口 —— **这是最关键的一条，必须助学组配合**
- 我们**不做登录系统**（学生不该在我们这再注册一次账号）。
- 我们所有接口都预留了 `student_id` 参数：**助学在调用时把"当前是哪个学生"的唯一 ID 传给我们**，我们就按这个 ID 记录他的答题和掌握度。
- 传什么我们就记什么，学号、UUID、内部 user_id 都行，**只要全局唯一且稳定不变**。

### 3) 输出给助教的接口 —— 教学重点数据（可直接生成 PPT/教案）
| 名称 | 位置 | 作用 | 出参 |
|---|---|---|---|
| `teaching_export(chapter=None)` | `feedback/feedback.py` | 输出"本章最该讲什么" | 薄弱知识点 Top5 + 每个点上学生的典型误区 + 建议讲解提示 |
| HTTP: `GET /api/teaching_export?chapter=…` | `demo/serve_quiz.py` | 同上 HTTP 版 | JSON |
| 教师看板 | `http://…/teacher` | 人看的界面，可一键导出 JSON / CSV | — |

### 4) 教师看板接口 —— 班级学情
| 名称 | 位置 | 作用 |
|---|---|---|
| `teacher_overview(chapter, student_id)` | `feedback/feedback.py` | 全班/按章/按学生的错误率、误区分类、趋势 |
| HTTP: `GET /api/teacher?chapter=…&student=…` | `demo/serve_quiz.py` | 同上 |

## 二、需要各组提供什么 / 思考什么

### 助学组 —— 必须给我们的
1. **【最重要】学生唯一 ID**
   > "你们系统里每个学生有没有一个唯一 ID？调我们出题/答题接口时能不能把这个 ID 带上？我们不自己做登录，接口已经预留 `student_id` 参数，你们传什么我们就按谁记录。"
2. **[Claude补充] 调用方式确认**：你们是直接 import 我们的 Python 函数（同一个进程），还是走 HTTP 接口（我们起一个服务）？这决定我们要不要把服务打包部署。
3. **[Claude补充] 练习/测试模式谁来决定**：我们支持两种模式（练习=即时给解析；测试=交卷后才给）。是助学在调用时告诉我们 `mode`，还是我们默认练习？
4. **[Claude补充] 学生历史数据要不要回传**：如果学生在助学那边也有学习行为（看了哪些知识点、卡在哪），能不能同步给我们？这会让 Phase 3 的推题准得多。

### 助教组 —— 需要他们思考的
1. **教师看板还想看什么**：我们已经做了（全班/按章/按学生 三个维度 + 错误率排行 + 误区按原因分类 + 趋势折线 + 导出）。请他们看一遍原型，说还缺什么。
2. **[Claude补充] 教学重点数据怎么接进他们的 PPT/教案生成**：我们的 `teaching_export` 输出的是结构化 JSON（薄弱知识点+学生误区+讲解建议）。需要确认：
   - 他们的课件生成需要什么字段？我们现在给的够不够？
   - 是他们主动来拉（调我们接口），还是我们定时推给他们？
3. **[Claude补充] 教案里要不要直接嵌入我们的题**：如果要，我们可以按知识点批量供题（含配图），需要他们说清要什么格式。

### UI 组 —— 需要他们做的
1. **美化两个界面**：学生答题端（`demo/quiz_page.html`）和教师看板（`demo/teacher_dashboard.html`）。
   - **功能逻辑我们已经跑通了，他们只做外观，不会返工。**
2. **[Claude补充] 需要他们定的几个交互问题**：
   - Bloom 标签（考点认知层级）要不要显示给学生？我们做了开关，默认显示。
   - "趁热打铁"现在是弹窗翻页（2-3题+小结），交互合不合理？
   - 配图的展示尺寸/是否可点击放大？
3. **[Claude补充] 我们能配合的**：我们可以把页面拆成"纯数据接口 + 前端"，他们用自己的框架重写前端，直接调我们的 `/api/*`。这样最省事。

## 三、硬件 / 部署方面要确认的 **[Claude补充，这块你还没想到]**

1. **数据库要换**：现在是 SQLite（一个文件，跟着压缩包走）。**这只适合我们自己开发调试。**
   一旦接入真实学生（几十上百人同时答题），必须换成**服务器数据库**（PostgreSQL 或 MySQL）。
   - 要问：**学校/团队有没有可用的服务器？谁来运维数据库？**
   - 好消息：我们的表结构不用改，只是换个连接方式，改动量很小。

2. **存储会持续增长，要有地方放**：
   - 答题记录：每人每题一条。1000 个学生 × 100 题 ≈ 10 万条 ≈ 几十 MB，不大。
   - **图片才是大头**：题目配图必须放**磁盘/对象存储**，数据库只存路径（我们已经这么设计了）。
   - 要问：**图片存哪？服务器本地磁盘，还是买对象存储（阿里云 OSS / 腾讯云 COS）？**
   - 我们的设计支持无缝切换：路径换成 OSS 的 URL 即可，代码一行不用改。

3. **模型调用要花钱**：反馈/批改/答疑都要调大模型。
   - 要问：**API Key 谁的？费用谁出？有没有调用量上限？**
   - 参考：一次反馈约几厘钱，但 100 个学生 × 每人 50 次 = 5000 次，得算清楚。

4. **服务要一直开着**：答题服务器得有人部署、有人守。
   - 要问：**部署在哪？谁负责重启/监控？**
