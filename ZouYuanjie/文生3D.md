# CODEX 进行三维建模

## 1. CODEX 进行三维建模的过程

CODEX 进行三维建模，是把自然语言需求转译为一组可执行的几何建模步骤，再通过 CAD 软件 API、脚本或几何内核完成实体生成。

一个典型流程如下：

1. 理解建模目标
   从文本中提取几何意图，例如圆盘、齿轮、中心孔、阵列孔、倒角、圆角等。

2. 参数化拆解模型
   将模型拆成一组明确的参数和约束，例如外径、厚度、孔径、孔数、分布半径、齿数、模数等。

3. 组织特征建模序列
   按照 CAD 的建模逻辑，生成草图、拉伸、旋转、切除、圆角、倒角、阵列、布尔运算等特征步骤。

4. 调用工具执行建模
   通过 SolidWorks API、脚本程序或其他建模引擎，将这些步骤转化为实际三维实体。

## 2. 这种方式的核心特点

这种建模方式的重点不在于“直接画形状”，而在于：

- 将文本需求转化为结构化建模意图
- 将结构化意图转化为可执行的几何程序
- 通过参数和特征实现稳定、可复用、可修改的建模过程

因此，它更接近“程序化 CAD”或“参数化特征建模”。

## 3. 对文生 3D 的启发

关键思路不是直接从文本黑盒生成一个最终模型，而是让智能体完成以下链路：

**自然语言需求 -> 参数化中间表示 -> 几何生成 -> 可视化预览 -> 用户反馈迭代**

一个较合理的系统可以分为以下几层：

### 前端交互层

负责：

- 接收用户自然语言输入
- 展示参数表单和可编辑配置
- 提供 3D 预览窗口
- 支持多轮修改与版本对比

### 智能体理解层

负责：

- 解析文本中的几何对象、尺寸关系和建模意图
- 将需求转换成中间表示，例如 JSON 特征树、CSG 描述、草图约束结构或 CAD 操作脚本

### 几何执行层

负责：

- 根据中间表示调用 CAD 内核、建模 API 或几何库
- 生成实体模型或网格模型
- 输出适合预览与下载的格式，如 glTF、STL、STEP 等

### 反馈迭代层

负责：

- 接收用户继续修改，例如“厚一点”“孔改成 6 个”“倒角改成 2mm”
- 只更新相关参数或特征，而不是整模重建
